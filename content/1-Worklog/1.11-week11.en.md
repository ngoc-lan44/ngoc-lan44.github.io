# Worklog Week 11: Core Backend Upgrade & Moderation Architecture (Phase 3)

### Week 11 Objectives:

- Migrate the Soft-Delete mechanism from S3 file storage to an ACID-compliant transactional system on Amazon DynamoDB to ensure data integrity.

### Tasks to Implement This Week:

|   Day   | Task | Start Date | Completion Date | Reference |

| **Mon** | **DynamoDB Data Model Design:** Split moderation data into two dedicated tables: State Table (partition key record_id) and Audit Table (sort key by revision) for paginated queries and full audit trails. | 19/10/2026 | 19/10/2026 | [AWS – DynamoDB Data Modeling](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/best-practices.html) |
| **Tue** | **ACID Transactions:** Implemented TransactWriteItems logic in dynamo_moderation_store.py to atomically update metadata, job status, and event logs, preventing race conditions during concurrent Admin actions. | 20/10/2026 | 20/10/2026 | [AWS – DynamoDB Transactions](https://docs.aws.amazon.com/amazondynamodb/latest/developerguide/transaction-apis.html) |
| **Wed** | **S3 Projection Mechanism:** Built a periodic snapshot sync pipeline from DynamoDB to S3 and updated Amazon Athena Views to point to snapshot v3, keeping BI Dashboard queries uninterrupted. | 21/10/2026 | 21/10/2026 | [AWS – Amazon Athena Views](https://docs.aws.amazon.com/athena/latest/ug/views.html) |

### Week 11 Results:

Successfully upgraded the moderation backend to ACID-compliant DynamoDB transactions with seamless S3/Athena projection and reduced Dashboard load latency by ~36%.
